# configurator

Output of the standalone **SOLECTRUS configurator** tool (the web-based setup
wizard that existed before HELIOS). A full stack with every collector plus S3
backups, but no `helios` service and no reverse proxy. Verifies that a freshly
configurator-generated installation can be adopted by HELIOS without loss.

## Highlights

- **Generic, non-HELIOS `.env` header** — the file was produced by the
  configurator, so it carries section banners like `### Dashboard application ###`
  instead of the `# Generated by HELIOS` marker. After import/export HELIOS
  rewrites it in its own style.
- **All collectors present**: `senec-collector` (local adapter), `shelly-collector`
  (single heatpump device), `mqtt-collector`, `forecast-collector` (Solcast) and
  `power-splitter`.
- **S3 backups for both databases** — `postgresql-backup` → `backup.postgresql`
  and `influxdb-backup` → `backup.influxdb`, with shared AWS credentials at the
  top of `backup:`. No `helios` or Traefik service (distinguishes this scenario
  from `full_stack` and `with_traefik_and_backup`).
- **Mixed sensor sources**: SENEC sensors (battery, grid, inverter, wallbox,
  system status), Shelly for `heatpump_power`, MQTT for `car_battery_soc`,
  forecast for `inverter_power_forecast`.
- **`INFLUX_EXCLUDE_FROM_HOUSE_POWER=HEATPUMP_POWER`** → stored per-sensor as
  `heatpump_power.exclude_from_house_power: true`, not as a top-level key.
- **Defaults not stored in `config.yaml`**: `FORCE_SSL=false`, `WEB_CONCURRENCY=0`,
  `INFLUX_POLL_INTERVAL=5` — silently dropped on import, re-added on export.
